Выполни 4-фазный анализ задачи. Фазы 0-3 — внутренний монолог. Итог — после.

PHASE 0 — EMPIRICAL GROUNDING (Презумпция Галлюцинации):
Запрещено строить план без аудита реальности. Сначала проверь: существуют ли модули, файлы, API о которых идёт речь? Какие данные подтверждают проблему? Без метрик, логов или наблюдений — задача отклоняется.

PHASE 1 — CONSTRAINTS AND DECOMPOSITION:
Определи [MUST_DO] (жёсткие ограничения) и [MUST_NOT_DO] (запреты). Выбери ментальную модель (First Principles, Inversion, Occam's Razor, Game Theory). Разбей задачу на атомарные шаги.

PHASE 2 — DIVERGENCE AND DRAFTING:
LATERAL INJECTION: до начала работы сформулируй 1 "дикую стратегию" — провокационный, контринтуитивный подход, ломающий шаблоны. Цель: избежать anchoring bias.
SCRATCHPAD: выполни логику декомпозиции. Расчёты, архитектурные наброски, черновой код. Свободно размышляй.

PHASE 3 — RED TEAMING AND CONVERGENCE:
ATTACK: выступи безжалостным критиком своего черновика. Выяви логические дыры, edge cases (null, overflow, timeout), уязвимости, side-effects, алгоритмическую неэффективность.
CONVERGE: синтезируй финальное решение. Интегрируй удачные элементы из LATERAL INJECTION, устрани уязвимости из ATTACK.
VERIFY: сверь решение с [MUST_DO] и [MUST_NOT_DO]. Если есть нарушения — вернись к SCRATCHPAD.

Формат вывода: максимальная плотность сигнала. Без преамбул, без извинений. Сразу к сути.
